# API – App Instance Manager

Generated by reading the controllers on 14.10.2026. **Source code wins** over this file; when they
disagree, fix this file in the same change. Base URL: `http://localhost:8888`. Swagger UI
(springdoc) is available on the running backend.

Entities are returned directly unless stated otherwise — their JSON shape is the entity's fields
(see `model/entity/**`).

## Network discovery – `NetworkDiscoveryController` (`/api/deploy/network`)

CORS allows only `http://localhost:5173` (`shared/config/CorsConfig`). Errors are `ProblemDetail`
with a Polish `detail`.

| Method | Path | Body / params | Response |
|---|---|---|---|
| GET | `/subnets` | – | `string[]` private IPv4 subnets, `/24`–`/30`, from the backend host's network cards and `aim.network.scan-subnets`, e.g. `["192.168.1.0/24"]` |
| POST | `/scan` | `NetworkScanRequest { cidr }` (must be an exact value from `/subnets`) | `202` `ScanJobResponse`; `400` subnet not allowed, `409` a scan is already running |
| GET | `/scan/current` | – | `ScanJobResponse` of the latest scan; `204` when there was none |
| POST | `/device-details` | `DeviceDetailsRequest { ip }` (must be inside a subnet from `/subnets`) | `DeviceDetailsResponse`; `400` address not allowed, `409` too many running, `503` nmap missing or failed |

`ScanJobResponse`: `{ id, cidr, state: "RUNNING"|"DONE"|"FAILED", stage: "SWEEP"|"PORTS"|"NAMES"|"DETAILS", percent, addressesTotal, addressesScanned, portsScanned, detailsTotal, detailsDone, deviceCount, devices: DiscoveredDevice[], details: { [ip]: DeviceDetailsResponse }, error|null }`.
`DiscoveredDevice`: `{ ip, hostname|null, macAddress|null, vendor|null, sshOpen, openPorts: number[], deviceType|null }`.
`DeviceDetailsResponse`: `{ ip, hostname|null, macAddress|null, osName|null, osFamily: "LINUX"|"WINDOWS"|"MAC"|null, deviceType|null, services: DiscoveredService[], hostScripts: ScriptResult[] }`.
`DiscoveredService`: `{ port, name|null, product|null, version|null, extraInfo|null, title|null, tlsSubject|null, cpe: string[], scripts: ScriptResult[] }`.
`ScriptResult`: `{ id, output }`.

## Inspection – `InspectionController` (`/api/inspections`)

CORS as above. Errors are `ProblemDetail` with a Polish `detail`. Never contains the password. Also started
automatically when `POST /api/deploy/server` or `/server/bulk` saves a server with a password.

| Method | Path | Body / params | Response |
|---|---|---|---|
| GET | `/servers` | – | `InspectionStatus[]`, one per server |
| POST | `/servers/{id}` | – | `202` `InspectionStatus` (an active run is reused); `400` no password; `404` missing server |
| GET | `/servers/{id}` | – | `{ status: InspectionStatus, sections: { key, label, category, value }[], fileCount }`; `404` |
| GET | `/servers/{id}/files` | query `parent` (empty = roots), `page`, `size` (default 200, max 500) | `FilePage`, folders first; `404` |
| GET | `/servers/{id}/files/search` | query `q`, `page`, `size` (default 100, max 500) | `FilePage`, match anywhere in the path, ignoring case; `404` |
| DELETE | `/servers/{id}/host-key` | – | `204`; `404` |
| GET | `/load` | – | `{ load }`, active plus queued runs; read by KEDA |

`InspectionStatus`: `{ serverId, name, ip, user, state: "QUEUED"|"RUNNING"|"DONE"|"FAILED"|null, stage: "CONNECTING"|"FACTS"|"FILES"|null, filesFound, error|null, failureKind: "LOGIN_REJECTED"|"HOST_KEY_CHANGED"|"OTHER"|null, dataFrom|null, truncated }`. `dataFrom`, `truncated`, `sections` and files describe the last successful run.
`FilePage`: `{ entries: { path, name, type: "f"|"d"|"l"|…, sizeBytes, owner, group, mode, modifiedEpochSeconds, denied }[], total }`.

The gRPC contract between the backend and the inspector is `proto/inspection.proto`.
